# STC12C5A60S2 / 828C 协议转换

UART2 接上位机，UART1 接测试主板，两路均为 115200、8N1。固件只完成命令转换、逐条记录解析和 JSON 发送。以本次用户确认的实施计划为执行依据；`01 参考资料`中的 PDF、Excel 和 V1.1 任务书用于核对命令、示例和数据含义。

## 使用流程

1. 上位机发送 `(START,1)`，UART1 输出 `test1\r\n`。1～4 都有效，不受软件默认模号限制。
2. 主板每发一条完整记录，UART2 就输出一条完整 JSON，末尾固定 `\r\n`。
3. `test` 标记忽略；`end` 结束会话，不追加汇总或 PASS 帧。
4. 下发 test 指令完成后，3 秒内没有有效记录则输出一次 `{"Result":"ERR"}\r\n` 并回到空闲。首条有效记录后不设帧间超时。
5. 新 START 重建会话。若正在发送 JSON，先发完该帧，再处理新命令。空闲时主板数据丢弃。

| 主板输入 | UART2 输出（均另加 CRLF） |
| --- | --- |
| `D1-1,9.0,6.0,V,(2-5=12.6),NG` | `{"MH":"1","Result":"NG","D1-1":"12.6V:NG"}` |
| `Open,10.0,0.0, ohm,(8-78=978.4,9-84=992.2,),NG` | `{"MH":"1","Result":"NG","Open":"978.4ohm:NG;992.2ohm:NG"}` |
| `Short,99.9,2.0,Mohm,(),OK` | `{"MH":"1","Result":"OK","Short":"OK"}` |

`MH` 来自本次 START 参数。`Result` 来自当前行末尾 OK/NG，大小写归一为大写，之前的 NG 不影响后续 OK。上下限只校验数值语法，不参与结果计算；上下限和测点编号不上报。多个值按原顺序用英文分号连接，每个值都带原单位和本行结果。保留数值精度、正负号、科学计数法及单位大小写。

项目名称、数量、顺序和数值均由实际输入决定，没有样本名称白名单。字段两端空格和制表符去除；允许括号内最后一个值后有逗号。主板行结束支持 CRLF、CR 或 LF。非 ASCII 名称和单位要求 UTF-8；反斜杠、双引号进行 JSON 转义，非法 UTF-8 或控制字符拒绝。项目名称不能为 JSON 保留键 `MH`、`Result`，以避免重复键。

`(RD_NUM)` 返回 `{"Result":"1"}\r\n`，数字由 `FIXTURE_DEFAULT_ID` 决定，支持 1～4。START 不依赖查询。上位机 `OK` 确认识别后忽略，支持单独两字节 OK 或带 CRLF，不等待 ACK。括号命令在收到 `)` 时即可执行，也可附 CRLF。

格式错误、超长、串口接收溢出均输出 ERR 并终止当前会话；已经开始发送的合法 JSON 会完整发完，再发 ERR。后续有效 START 可恢复。尚未收到行结束的片段只缓存，不生成伪造结果；首条记录仍受 3 秒超时约束。空会话直接收到 end 作为无有效结果报 ERR。

## 工程结构和容量

| 目录 | 内容 |
| --- | --- |
| System | 双串口中断、接收环形缓冲、非阻塞发送、通信计时 |
| App | 命令与记录解析、流式 JSON 编码、会话管理 |
| Public | STC12C5A60S2.h、公共类型、板级配置 |
| User | STARTUP.A51、初始化与主循环 |

不使用动态内存，不保存整轮结果，也不另外分配完整 JSON 缓冲。先在 UART1 环形缓冲中校验完整记录，再随编码逐步释放原始数据。中断只搬运字节。

默认固件容量位于 `Public/board_config.h`：单行 511 字节（不含行结束），项目名称 31 字节、单位 8 字节（UTF-8 按字节计），命令 23 字节；UART1 环形区 768 字节、UART2 环形区 64 字节，各保留一个槽区分空满。超限明确报 ERR，不静默截断。它们是 MCU 内存预算，不能解释为主板协议的固定长度。调整容量后需要重新检查链接 RAM 和连续流量。

两边波特率相同，JSON 可能比输入更长，有限缓冲无法保证任意无限连续输入均不溢出。已验证现有样本连续输入；实际主板最坏发送节奏仍需实测。溢出路径会明确报错并可重新 START。

旧传感器、I²C、Modbus、压力、LED 等 31 个无关源码/头文件已移除，Keil/EIDE 仅引用上表文件。旧 Objects、Listings、build 及源码旁的编译缓存尚有残留，不属于当前构建输入。清理这些生成物的命令被自动审批以 `blocked by policy` 拒绝；新工程输出使用独立目录，禁止把旧 Project.hex 当作本次固件。

## 时钟、接线和构建

UART1：P3.0/RXD、P3.1/TXD；UART2：P1.2/RXD2、P1.3/TXD2。UART2 选择默认引脚。双方 TX 接对方 RX 并共地，电平按实际主板/串口适配器匹配。

STC12 的内部 RC 由 ISP 选择和校准；固件不套用 STC8 时钟寄存器。当前 `PROJECT_FOSC_HZ=0` 表示尚未提供 ISP 实测频率，正式目标会报编译错误。填入实际 Hz 后，选择 Keil `828C ISP MEASURED` 目标。双串口共享 BRT，1T、倍速，按 `Fosc/(16*N)` 计算；误差超过 2% 则拒绝构建，需要在 ISP 中调整 RC 到适合生成 115200 的频率并重新实测。

打开 `Project.uvproj` 可选择 `828C TEST CLOCK` 进行构建验证。该目标通过 `BRIDGE_BUILD_TEST` 使用 **11.0592 MHz 测试假设**，输出 `BuildTest/Bridge828C_TEST_CLOCK.hex`，不能据此认定已匹配实物内部 RC。EIDE 当前也配置为这个测试目标（SMALL 模型）；实测使用时移除测试宏并填写真实频率。

命令行构建（Python 3，默认 Keil 路径 D:/Keil_v5）：

```text
python "04 测试验证/build_keil.py"
python "04 测试验证/build_keil.py" --fosc <ISP实测Hz>
```

第二条输出 `BuildMeasured/Bridge828C.hex`。仅接受当前构建成功的产物；失败时旧目录中可能留有上次成功的 HEX，不能凭文件存在判断成功。脚本保留 build.log，并检查链接地址范围和栈空间。Timer0 负责约 1 ms 通信计时，实板需要测量 RC 误差、中断重载延迟对 3 秒窗口的影响。

已完成 Keil C51/A51/BL51/OH51 构建与 µVision 直接重建，均无警告、无错误；RAM/ROM 数量以最新 build.log 和 .m51 为准。已覆盖样本逐条核对、连续收发、通用名称/数值/单位、分段、多值、模号、超时、重新 START 和异常恢复。

以下尚未完成：ISP 实测频率配置、烧录、实板双串口压力测试、逻辑分析仪测量波特率/首帧超时、真实 828C 上位机逐帧及多值字符串接收验收。原资料存在整轮汇总、模号过滤等行为，与本次明确确认的逐条 JSON / START 参数映射不同；这里按确认后的方案实现，不能仅凭 JSON 语法有效就宣称原上位机已接受。
