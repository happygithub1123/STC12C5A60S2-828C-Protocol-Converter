# 828C 协议转换验证

汇总结果、串口对照样例及现场验收表见 [测试验证.md](测试验证.md)；阶段历史见 [程序编写验证记录](程序编写验证记录.md)。

实际串口调试请先看 [串口调试实例.md](串口调试实例.md)，其中包含双窗口接线、可复制数据、预期 JSON，以及 X5、模号核对、查询和恢复步骤。可载入的数据在 [串口测试数据](串口测试数据) 中。

在仓库根目录运行（Python 3，Windows）：

```text
python "04 测试验证/run_tests.py"
python "04 测试验证/build_keil.py"
```

主机测试通过 vswhere 查找 Visual Studio C++ 工具链；Keil 默认路径 D:/Keil_v5，可用 --keil 指定其他安装。内部 RC 固定为 22.1184 MHz，两路串口均为 115200、8 位数据、无校验、1 位停止位。默认构建输出 Objects/Bridge828C.hex。

## 自动验证

当前 180 项全部通过。主机模型编译与 MCU 相同的 App、Control、Uart1、Uart2 源码，模拟串口、时间、输入寄存器；不模拟 8051 指令执行耗时。

- 当前样本 28 条记录独立 Python 参考转换与 C 固件逐字节比对，Open 的 36 个测量组只上传首组，后续帧顺序完整。
- 87 µs 字符间隔及 50 µs 主循环调度下的样本连续输入；另覆盖 150 条生成记录与环形缓冲回绕。
- START1～4 立即核对唯一有效模号；全高、多路低或模号不一致立即 ERR，修正电平不自动启动；输入恢复后可直接重新发送有效 START，不依赖 X5 电平或历史错误。
- 四路 MH 映射、首次轮询 X5 已低；活动会话断开／改号／多路低主动报一次 ERR，接回不自动恢复。X5 持低时 end 后仍监测，释放后结束该次监测。
- X5 来源释放即停测、不报 ERR，START 来源不受释放影响；断开后可新 START 恢复。再拉低无需 end 即换新 MH；待执行 X5 请求释放即取消、执行前重新核对。查询／JSON／test 发送中仍监测，完整旧帧、待报 ERR、新启动按顺序执行。
- 未发送的 test 可取消；已发送第 1～6 字节时发生故障，指令仍完整；同次 START／X5 不重复启动，重新启动清理旧记录片段。
- test 指令的 CRLF 字节、启动后 74 秒无数据不超时、长帧间间隔、旧 16 位计时回绕边界、发送中切换会话。
- RD_NUM 按 PDF 返回 Result JSON；无模号时分段／连续查询每条只回复一次 ERR；全部 16 种输入组合、查询不改变会话和 MH、查询回复与 JSON 不交织；不带 CRLF 的 OK、旧数据丢弃及异常恢复。
- 通用名称、单位、精度、科学计数法、空值/单值/多值、首组测点转义、UTF-8 文本、非法编码及控制字符拒绝。
- 后续未上传组的结构及数值校验、511/512 字节边界、UART1/UART2 溢出、发送中溢出仍完成合法 JSON。
- 所有回复均校验 JSON 语法、唯一键和 CRLF；RD_NUM 成功回复为 `{"Result":"x"}\r\n`，不接受帧间字节交织。

2. 两路独立串口分别接主板侧和上位机侧。逐一发送 START1～4，只有匹配的 X 输入唯一为低才启动；UART1 字节为 `74 65 73 74 0D 0A`。
3. 验证全高、多路低、模号不一致立即 ERR，修正电平不自动启动；X1～X4 与 X5 接线正确，活动会话模号失效停测；接回或查询不自动恢复，新的有效 START 或重新有效触发 X5 可以恢复。X5 来源释放停止上传；START 来源释放 X5 不受影响。
4. test 后等超过 3 秒不发数据应无 ERR，随后发记录仍上传；回放样本、新项目及最坏主板流量，检查溢出和恢复。

6. 连接真实 828C 上位机，确认查询模号绑定、连续 JSON 及首组字符串均被接受，保存软件版本、配置、抓包及界面记录。
