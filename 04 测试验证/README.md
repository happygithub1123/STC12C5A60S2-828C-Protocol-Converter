# 828C 协议转换验证

汇总结果、串口对照样例及现场验收表见 [测试验证.md](测试验证.md)；阶段历史见 [程序编写验证记录](程序编写验证记录.md)。

在仓库根目录运行（Python 3，Windows）：

```text
python "04 测试验证/run_tests.py"
python "04 测试验证/build_keil.py"
```

主机测试通过 vswhere 查找 Visual Studio C++ 工具链；Keil 默认路径 D:/Keil_v5，可用 --keil 指定其他安装。默认正式频率为 22118400 Hz，可显式传 --fosc 22118400。默认构建输出 BuildMeasured/Bridge828C.hex，不再使用旧测试时钟目标。

## 自动验证

当前 75 项全部通过。主机模型编译与 MCU 相同的 App、Control、Uart1、Uart2 源码，模拟串口、时间、输入寄存器；不模拟 8051 指令执行耗时。

- 当前样本 28 条记录独立 Python 参考转换与 C 固件逐字节比对，Open 的 36 个测量组只上传首组，后续帧顺序完整。
- 87 µs 字符间隔及 50 µs 主循环调度下的样本连续输入；另覆盖 150 条生成记录与环形缓冲回绕。
- START1～4、对应输入引脚、其他通道不误触发、初始为低、延迟变低、999/1000 ms 边界、超时只报一次、新 START 重置等待、输入变化不重复启动。
- test 指令的 CRLF 字节、发送完成后的 3 秒首帧超时、首帧后的长间隔、16 位计时回绕、发送中切换会话。
- RD_NUM、不带 CRLF 的 OK、等待输入期间命令可处理、旧主板数据丢弃及异常后恢复。
- 通用名称、单位、精度、科学计数法、空值/单值/多值、首组测点转义、UTF-8 文本、非法编码及控制字符拒绝。
- 后续未上传组的结构及数值校验、511/512 字节边界、UART1/UART2 溢出、发送中溢出仍完成合法 JSON。
- 每条输出校验 JSON 语法、唯一键和 CRLF，不接受部分 JSON。

## 实物验收（待执行）

1. STC-ISP 设置内部 RC 22.1184 MHz，烧录本轮成功构建的 HEX；测 UART1/UART2 实际 115200、8N1 波形。
2. 两路独立串口分别接主板侧和上位机侧。逐一发送 START1～4，只拉低对应输入，确认 UART1 只收到 `74 65 73 74 0D 0A`。
3. 验证输入全高、其他输入为低、输入初始为低、延迟变低、1 秒超时、新 START 替换、触发后持续低及电平变化不重复启动。
4. 测量 3 秒首条记录窗口从 test 发送完成开始；回放当前样本和新项目，与 sample_expected.jsonl 对比，并测试最坏主板流量、溢出和恢复。
5. 连接真实 828C 上位机，确认连续 JSON 均被接收，首组测点、数值、单位和结果完整显示，保存软件版本、配置、抓包及界面记录。

原版本的实物转换成功由使用者确认。本轮新增行为的自动验证、实板验证、真实上位机验收必须分别记录；本次未执行烧录或实物验收。
