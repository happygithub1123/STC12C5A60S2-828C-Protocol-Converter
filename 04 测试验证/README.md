## 当前验证方式

在仓库根目录运行（Python 3，Windows）：

```text
python "04 测试验证/build_keil.py"
```

Keil 默认 D:/Keil_v5，可用 --keil 指定安装目录。内部 RC 固定 22.1184 MHz，两路串口统一为 115200、8 位数据、无校验、1 位停止位。没有 Python 时也可直接在 µVision 中打开 Project.uvproj 并重建目标 828C Protocol Conversion Project。

2026-10-29 按要求移除电脑模拟支持及配套脚本。固件直接访问 MCU 寄存器，功能验证使用实际板卡、双串口回放和下方实物验收步骤。保留构建脚本、串口样本、期望输出和历史验证记录。

## 历史主机测试

移除前的固件提交 `a980899` 曾通过 **152 项主机测试**。下列内容仅记录当时覆盖范围，当前不再提供主机模拟构建和运行入口；如需复现，应检出历史提交。该阶段 HEX 的 SHA256 为 `FA1F9820E4205CC37FFC8B32F47B90D0AEFD2BCACC0323B96AE01C012955857D`。

- 28 条实际样本逐字节匹配，Open 的 36 组仅上传首组；150 条生成记录、87 µs 字符间隔、50 µs 主循环调度和环形缓冲回绕。
- 空值、单值、多值、尾逗号、通用名称与单位、精度与正号、科学计数法、测点 JSON 转义、UTF-8 及非法编码。
- 四路 START／MH、模号不匹配、全部 16 种查询输入组合、RD_NUM 的 Result JSON、不带 CRLF 的 OK、查询不启动或恢复会话。
- 按键高／低各稳定 20 ms、上电按住／高电平不足 20 ms、按下／释放抖动、长按一次、两个 16 位计时回绕位置。
- 四路按下松开仍上传；四路分别在按住／松开／START 状态下断开、改号、多路低，主动一次 ERR，接回不恢复；新按键或有效 START 恢复。
- test／等待首帧／JSON／接收状态的忙时按键忽略，消抖期间收到 end 也不补发；持续按住跨过 end 不启动下一轮。
- 空闲已接受按键松开不取消，等待查询／命令边界；执行前模号变化取消；START 优先且不重复启动。
- UART1 指令第 1～6 字节发生模号失效仍补齐；未发可取消；输出中失效先完整 JSON／查询，再 ERR，再有效 START，旧数据不混入。
- 74 秒无数据不超时、511／512 字节、两路溢出、错误恢复、旧片段清理、六条可操作样本及正常 end 回到空闲。

旧版“松开 X5 停测”“忙时按键重启”“上电已低自动启动”的测试预期已替换，不将原 180 项的结果当作本轮行为通过。

Keil 检查片内 256 字节 IRAM、1024 字节 XRAM、60 KiB 程序地址范围，以及至少 64 字节静态栈余量。本轮 data=126、xdata=884、code=5233 字节，栈起始 0x7D、余量 131 字节；两种构建均零错误、零警告。

HEX 为源码工程 Objects/Bridge828C.hex。历史自动日志和中间文件的备份位置见程序编写验证记录。Keil 日志可重新构建生成；移除电脑模拟后的实际构建结果也记于程序编写验证记录。
