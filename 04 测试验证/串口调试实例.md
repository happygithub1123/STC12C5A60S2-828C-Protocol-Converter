# 串口调试实例

本文件给出可以实际操作的发送内容和预期返回。两路串口统一设置：**115200、8 位数据、无校验、1 位停止位**。

当前 95 项自动测试使用同一份 C 协议源码，覆盖下列关键流程及六条连续输入文件；串口接线、实际输入电平和真实上位机仍需按步骤实测后填写结果。

## 1. 调试接线与发送设置

用两个串口调试窗口分别模拟上位机和测试主板。模拟主板时暂不接真实主板，由窗口 B 发出主板记录。

| 窗口 | 用途 | USB 串口 TX 接 MCU | USB 串口 RX 接 MCU |
| --- | --- | --- | --- |
| A | 模拟上位机，接 UART2 | P1.2／RXD2 | P1.3／TXD2 |
| B | 模拟主板，接 UART1 | P3.0／RXD | P3.1／TXD |

转换板与两个串口适配器共地，使用匹配板卡接口的串口电平。X1～X4 分别为 P3.2、P3.3、P3.4、P3.5；X5 启动输入为 P3.6。输入接 GND 表示低电平有效，释放后由内部弱上拉保持高。X1～X4 必须且只能有一路接低，未测试 X5 时保持 X5 为高。

两个窗口均使用文本发送。主板记录发送时勾选“追加 CRLF／回车换行”。下文代码块只复制实际文本，**不要把文字 `\r\n` 作为四个字符发送**。若发送工具已追加 CRLF，就不用手工再加一次。

先把要发送的主板记录设置为快捷发送按钮或载入文件。窗口 B 收到 test 后即可发送；也可以等超过 3 秒再发送，当前没有首帧或帧间超时。

## 2. 先跑通最简单的一例

1. 在窗口 B 预设以下内容，勾选追加 CRLF：

```text
Short,99.9,2.0,Mohm,(),OK
```

2. 将 X1（P3.2）接 GND，其他输入释放。
3. 在窗口 A 发送：

```text
(START,1)
```

4. 窗口 B 应收到小写 test 和换行，十六进制为：

```text
74 65 73 74 0D 0A
```

5. 点击窗口 B 的 Short 快捷发送按钮。
6. 窗口 A 应收到以下一行，帧尾实际为 CRLF：

```json
{"MH":"1","Result":"OK","Short":"OK"}
```

等待超过 3 秒也不应因超时报 ERR。没有有效 START 或 X5 会话时，主板记录被丢弃；成功启动前会清除旧接收内容。

## 3. 一次发送六条，检查连续转换

先在窗口 B 载入 [主板连续输入.txt](串口测试数据/主板连续输入.txt)，准备好发送。文件按行发送即可；若工具可设置行间延时，可设为 100 ms。

将 X1 接 GND，窗口 A 发 `(START,1)`；窗口 B 收到 test 后立即发送整份文件：

```text
test
D1-1,9.0,6.0,V,(2-5=12.6),NG
D1-2,10.5,7.5,V,(5-2=8.20),ok
Open,10.0,0.0, ohm,(8-78=978.4,9-84=992.2,),NG
Short,99.9,2.0,Mohm,(),OK
Custom,10,0,,(p=1.250,q=2.500),OK
ILeak,1.000,0.000,mA,(1-2=+0.0100,3-4=0.0200),OK
end
```

窗口 A 应按顺序收到下面六行，与 [上位机预期输出_模号1.jsonl](串口测试数据/上位机预期输出_模号1.jsonl) 对照：

```json
{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}
{"MH":"1","Result":"OK","D1-2":"5-2=8.20 V:OK"}
{"MH":"1","Result":"NG","Open":"8-78=978.4 ohm:NG"}
{"MH":"1","Result":"OK","Short":"OK"}
{"MH":"1","Result":"OK","Custom":"p=1.250:OK"}
{"MH":"1","Result":"OK","ILeak":"1-2=+0.0100 mA:OK"}
```

检查要点：test 和 end 不单独返回 JSON；Open、Custom、ILeak 都只上传第一组；空单位没有多余空格；数值精度、正号和单位大小写保留；后面的 OK 不继承前面的 NG。end 后不追加汇总帧。

## 4. 四个模号分别测试

每一行均重新开始一次测试：先接低对应 X，再发送该 START；收到 test 后在窗口 B 发送同一条 Short 记录。

```text
Short,99.9,2.0,Mohm,(),OK
```

| 接低的输入 | 窗口 A 发送 | 窗口 B 应收到 | 窗口 A 应收到 |
| --- | --- | --- | --- |
| X1／P3.2 | `(START,1)` | test＋CRLF | `{"MH":"1","Result":"OK","Short":"OK"}` |
| X2／P3.3 | `(START,2)` | test＋CRLF | `{"MH":"2","Result":"OK","Short":"OK"}` |
| X3／P3.4 | `(START,3)` | test＋CRLF | `{"MH":"3","Result":"OK","Short":"OK"}` |
| X4／P3.5 | `(START,4)` | test＋CRLF | `{"MH":"4","Result":"OK","Short":"OK"}` |

每次只允许一条 X1～X4 为低。START 参数必须与实际有效通道一致，没有软件默认模号；不按优先级从多条低输入中选取。

## 5. 模号立即校验与异常恢复

每个场景从空闲开始，X5 保持高，窗口 B 不发送数据。

| X1～X4 电平 | 窗口 A 发送 | 预期 |
| --- | --- | --- |
| 全高 | `(START,1)` | 立即一次 ERR，不发 test |
| 仅 X1 低 | `(START,2)` | 立即一次 ERR，不发 test |
| X1、X2 同时低 | `(START,1)` | 立即一次 ERR，不发 test |
| 仅 X2 低 | `(START,2)` | 立即发送一次 test，随后可上传 MH=2 数据 |

前三项出错后，再把正确输入接低也不会自动启动；须重新发匹配的 START。连续等 4 秒不应重复报错。这里的“立即”指命令收完整并执行后处理，不等待 1 秒或 3 秒；若正在输出 JSON，会先完成该帧。

## 6. 超过 3 秒后仍可上传

X1 唯一接低，窗口 A 发送 `(START,1)`。窗口 B 收到 test 后，**至少等 4 秒且不发送任何主板记录**。

窗口 A 不应出现 ERR。然后从窗口 B 发送：

```text
Short,99.9,2.0,Mohm,(),OK
```

窗口 A 应立即收到：

```json
{"MH":"1","Result":"OK","Short":"OK"}
```

继续等 4 秒，再发送 D1-1，仍应正常转换。记录没有行结束时只缓存，补齐后才上传。

## 7. 错误数据与恢复

X1 唯一接低，窗口 A 发 `(START,1)`，收到 test 后，窗口 B 发送以下错误记录并追加 CRLF：

```text
D1-1,9.0,6.0,V,(2-5=abc),NG
```

窗口 A 应只收到 ERR，不应收到部分 D1-1 正常 JSON。

恢复步骤：窗口 A 重新发 `(START,1)`，窗口 B 再次收到 test 后发送：

```text
D1-1,9.0,6.0,V,(2-5=12.6),NG
```

预期：

```json
{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}
```

即使只上传首组，后面的组也必须符合格式。例如下面这条也应报 ERR：

```text
Open,10.0,0.0,ohm,(8-78=978.4,broken),NG
```

测试这条错误记录前，也要先重新 START 并完成输入触发。

## 8. 查询、确认和非法命令

以下命令在空闲状态测试，均从窗口 A 发送。可复位转换板进入空闲，或先完成一次有效记录后发送 end。

| 发送内容 | 预期 |
| --- | --- |
| 仅 X1 为低时发送 `(RD_NUM)` | 返回 `{"Result":"1"}`＋CRLF，不发 test |
| 仅 X2 为低时发送 `(RD_NUM)` | 返回 `{"Result":"2"}`＋CRLF，不发 test |
| 仅 X3 为低时发送 `(RD_NUM)` | 返回 `{"Result":"3"}`＋CRLF，不发 test |
| 仅 X4 为低时发送 `(RD_NUM)` | 返回 `{"Result":"4"}`＋CRLF，不发 test |
| X1～X4 全高或多路低时发送 `(RD_NUM)` | 返回 ERR，不改变当前会话 |
| `OK` | 忽略，无回复，不向主板发指令 |
| `(START,0)` | 返回 ERR，不发 test |
| `(START,5)` | 返回 ERR，不发 test |
| `(BAD)` | 返回 ERR，不发 test |

X1～X4 全部释放为高、X5 保持高时，在窗口 A 发送 `(RD_NUM)`，应收到下面一行（末尾实际另有 CRLF）：

```json
{"Result":"ERR"}
```

再次查询仍只对本条命令回复一次 ERR，不会发送 test，也不自行重复报错。有模号时则按表格返回 Result JSON，用于上位机绑定串口。

RD_NUM 查询当前实际输入，与上一轮模号无关。它仅查询，不启动测试：即使会话 MH 已锁定为 1，改为仅 X4 低后查询会回复 `{"Result":"4"}`，但原会话的 JSON 仍使用 MH=1。

文本工具发送 `(START,1)` 与十六进制发送下列内容等效：

```text
28 53 54 41 52 54 2C 31 29 0D 0A
```

## 9. X5 直接启动与新 START

### 9.1 不发 START，使用 X5 启动

1. 从空闲开始：仅 X3（P3.4）接 GND，X1、X2、X4、X5 释放为高。
2. 将 X5（P3.6）接 GND，不从窗口 A 发送 START。
3. 窗口 B 应收到一次 `test`＋CRLF，然后发送 Short＋CRLF。
4. 窗口 A 应收到：

```json
{"MH":"3","Result":"OK","Short":"OK"}
```

5. 窗口 B 发送 end＋CRLF，X5 一直保持低，继续等 4 秒：不得再发送 test。
6. 将 X5 释放为高，再接 GND，窗口 B 才应收到第二次 test。

将唯一有效通道依次换为 X1、X2、X4，重复上述步骤，检查 MH 分别为 1、2、4。上电前 X5 已低且模号有效时，也应启动一次。

X1～X4 全高或多路低时触发 X5：只回复一次 ERR，不发 test。修正模号后须将 X5 恢复高再拉低，才能重试。

### 9.2 会话中 X5 不重复启动

先用 START1 启动并使 X5 保持高。等待主板数据或正在上传 JSON 时将 X5 拉低，然后发送 Short 和 end。窗口 B 只能收到原来的那次 test；回到空闲后也不补发。须释放 X5 为高再拉低，才能开始下一轮。

### 9.3 新 START 切换模号

先仅 X1 低并发 START1，窗口 B 发送 D1-1。再释放 X1、仅接低 X2，从窗口 A 发 START2。若前一条 JSON 正在输出，必须先发完整，再向窗口 B 下发新的 test。

窗口 B 第二次收到 test 后发送 Short，应得到 MH=2 的 OK。后续 X1 变化不会影响 MH；若新 START 的模号不匹配，则回复 ERR 并结束旧会话。

## 10. 分段接收与结束标记

### 10.1 一条主板记录分两次发送

先使 X1 唯一为低并发送 START1，收到 test 后，从窗口 B 依次发送以下两组。第一组不追加任何换行，第二组追加 CRLF；两组之间也可停顿超过 3 秒。

| 次序 | 文本内容 | 发送设置 | 预期 |
| --- | --- | --- | --- |
| 第一组 | `D1-1,9.0,6.0,V,(2-` | 不追加行结束 | 暂无 JSON |
| 第二组 | `5=12.6),NG` | 追加 CRLF | 返回完整 D1-1 JSON 一条 |

最终仍应得到：

```json
{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}
```

### 10.2 end 结束会话

先按第 2 节收到一条 Short 正常 JSON，再从窗口 B 发送 `end`＋CRLF。end 本身无回复，此后直接发送主板记录应被忽略。

重新发 START 并触发输入后，记录才再次被转换。不要在还未收到第一条有效记录时发送 end；空会话直接 end 会报 ERR。

## 11. 常见现象定位

| 现象 | 优先检查 |
| --- | --- |
| START 后立即 ERR，窗口 B 没有 test | X1～X4 是否唯一为低，是否与 START 参数相同 |
| test 后超过 3 秒仍无回复 | 没有首帧超时是正常行为；发送完整主板记录后应立即上传 |
| 一发主板记录立即 ERR | 英文逗号和括号、数值格式、名称／单位长度、UTF-8 编码 |
| 发数据完全没回复 | 是否已经有效 START／X5 启动，是否带行结束，是否已 end 或错误退出 |
| 显示文字 `\r\n`，没有实际换行 | 发送了反斜杠字符；改用工具追加 CRLF 或发 0D 0A |
| 返回模号不符合预期 | START／X5 启动时锁定的实际输入；RD_NUM 只查询，不改变本轮 MH |
| X5 一直接低却没有再次 test | 持续低只触发一次；结束会话后先释放高，再拉低 |
| Open 只返回第一组 | 当前规则如此；首组应保留测点、数值、单位和本条结果 |

实板逐项记录结果，使用 [测试验证.md 的现场记录表](测试验证.md)；自动测试结果与实物验收结果分开记录。
