## 2. 配置与复现方式

| 参数 | 配置 |
| --- | --- |
| MCU | STC12C5A60S2 |
| 时钟 | 内部 RC 22.1184 MHz，ISP 设置与固件配置一致 |
| UART1 | 主板侧，P3.0 RX／P3.1 TX，115200、8N1 |
| UART2 | 上位机侧，P1.2 RX／P1.3 TX，115200、8N1 |
| X1～X4 | P3.2～P3.5，准双向输入、内部弱上拉、低电平有效 |
| 输入等待 | START 执行后 1000 ms 内检测对应输入 |
| 首条记录等待 | `test\r\n` 发送完成后 3000 ms |
| 单行输入容量 | 511 字节，不含 CR／LF |
| 名称／单位容量 | 31／8 字节，UTF-8 按字节计数 |

在仓库根目录运行：

```powershell
# 同一份固件 C 源码的主机自动测试，需 Visual Studio C++ 工具链
python "04 测试验证/run_tests.py"

# Keil 编译、链接、RAM 检查及 HEX 生成，默认 D:/Keil_v5
python "04 测试验证/build_keil.py"
```

µVision 打开源码工程 `Project.uvproj`，选择目标 `828C INTERNAL RC 22.1184MHz` 后执行 Rebuild。HEX 位于 `02 软件源码/顺天祥协议转换/BuildMeasured/Bridge828C.hex`。

主机测试使用实际 App、Control、Uart1、Uart2 源码，模拟时间、GPIO 寄存器和串口字节；不模拟 8051 指令耗时、RC 漂移或物理电气行为。

## 3. 已通过的自动测试

下表归纳 75 项用例的覆盖范围，逐项输入、串口输出、接收峰值和错误码见本地 `results/test_results.txt`。

| 类别 | 输入／操作 | 预期与已验证结果 |
| --- | --- | --- |
| 四路映射 | 分别发送 START1～4 | 只检测 X1～X4 对应引脚，MH 与本次通道一致 |
| 其他输入干扰 | 其他三路为低，对应路为高 | 不下发 test；对应路变低后才触发 |
| 初始为低 | 先置对应输入低，再发 START | 立即触发，仅发送一次 `test\r\n` |
| 等待边界 | 999 ms 与 1000 ms 检测到低 | 999 ms 可启动；1000 ms 按超时处理 |
| 输入超时 | 对应输入始终为高 | 一次 ERR，不发 test，回到空闲；新 START 可恢复 |
| 会话替换 | 等待期间发新的 START | 替换对应输入和模号，并重新计时 |
| 触发锁定 | 启动后改变 X 输入或保持低 | 不重复启动，不改变本次 MH |
| 触发前主板数据 | 等待输入时注入旧记录、片段或溢出 | 丢弃旧内容，不混入触发后的新结果 |
| 辅助命令 | RD_NUM、带／不带 CRLF 的 OK | 查询默认模号；OK 忽略，不阻塞启动 |
| 首条记录超时 | test 发完后没有有效记录 | 从发送完成开始计 3 秒，只回复一次 ERR |
| 帧间间隔 | 首条有效记录后暂停超过 3 秒再发下一条 | 无额外帧间超时，下一条正常上传 |
| 计时回绕 | 毫秒计数跨越 65535 | 两类超时仍正确 |
| 样本回放 | 当前 28 条记录连续输入 | 逐条匹配新规则，Open 的 36 组仅上传第一组 |
| 通用转换 | 变化名称、数量、顺序、精度、单位和 OK／NG | 无样本白名单，使用本条记录的内容和结果 |
| 空／单／多值 | 空括号、一个值、多个值和尾逗号 | 空值上传结果；非空只上传首组测点、数值、单位 |
| JSON 编码 | 名称、单位、测点含中文、引号和反斜杠 | UTF-8 有效，字符串正确转义，键名唯一，帧尾 CRLF |
| 无效数据 | 格式错误、非法数值、保留键、控制字符、非法 UTF-8 | ERR，无部分正常 JSON；未上传组也做校验 |
| 分段接收 | 将命令和记录拆为多个片段 | 完整前不执行转换；收齐后只输出一次 |
| 长度边界 | 511 与 512 字节记录 | 511 字节可处理；512 字节明确 ERR |
| 溢出恢复 | UART1／UART2 缓冲溢出 | 明确 ERR；新 START 后可正常工作 |
| 输出中异常 | 正在发送 JSON 时发生溢出或收到新 START | 当前合法 JSON 完整发送后再报错或切换 |
| 连续发送 | 87 µs 字符间隔，另测 50 µs 主循环调度 | 当前样本保持顺序、内容完整 |
| 缓冲回绕 | 150 条生成记录 | 环形缓冲跨边界后仍正确转换 |
| 主板标记 | test、end | test 忽略；end 结束会话，不追加汇总帧 |

### 3.1 可直接用于串口对照的样例

先将 X1 拉低，再从 UART2 发送 `(START,1)`。UART1 必须收到：

```text
test\r\n
```

对应十六进制：`74 65 73 74 0D 0A`。下列 JSON 均为 UART2 输出，末尾另外附 `0D 0A`。

| UART1 主板输入（另加 CRLF） | UART2 预期输出 |
| --- | --- |
| `D1-1,9.0,6.0,V,(2-5=12.6),NG` | `{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}` |
| `Open,10.0,0.0, ohm,(8-78=978.4,9-84=992.2,),NG` | `{"MH":"1","Result":"NG","Open":"8-78=978.4 ohm:NG"}` |
| `Short,99.9,2.0,Mohm,(),OK` | `{"MH":"1","Result":"OK","Short":"OK"}` |
| `Custom,10,0,,(p=1.250,q=2.500),OK` | `{"MH":"1","Result":"OK","Custom":"p=1.250:OK"}` |

连续发送 NG 记录后再发送 Short／OK，后者的 Result 必须为 OK，不继承前条 NG。
