# STC12 通讯过程 3D 交互仿真

面向项目讲解、协议学习和交互演示。三维场景展示 **828C 上位机 ↔ UART2 ↔ STC12C5A60S2 ↔ UART1 ↔ 测试主板**，并同步展示模号输入、软件处理步骤、串口字节及 JSON 结果。

## 启动

1. 本机安装 Node.js 20 或更新版本（开发验收环境为 Node.js 24.15.0）。
2. 双击本目录的 **启动仿真.cmd**。浏览器会自动打开本机地址。
3. 点击 **一键演示**，或在初始状态点击 **播放**。右侧可选择六类场景。
4. 关闭启动窗口或按 Ctrl+C 停止服务。

也可在本目录运行 `node server.mjs`；`node server.mjs --no-open --port=8280` 使用固定端口且不自动打开浏览器。默认随机选择可用端口，只监听 127.0.0.1。请通过服务打开，ES Modules 和样本读取不支持直接双击 index.html。

无需 npm install、编译或联网。Three.js、OrbitControls 与样本均随目录保存；模型由代码生成，使用本机系统字体。浏览器需要支持 WebGL2，建议 Chrome 或 Edge。WebGL 初始化失败时显示提示，协议面板和日志仍可使用。

## 操作

- **全景 / 芯片内部**：切换整机链路与芯片内部处理示意；鼠标拖动旋转，滚轮缩放。
- **播放 / 暂停 / 单步**：单步只发布一个逻辑事件，暂停冻结仿真进度与数据包运动。空闲且没有待执行动作时，播放重新开始所选场景；等待主板数据的活动会话不会被重启。
- **演示速度**：控制事件发布和数据包动画速度，不改变协议输出。时间栏显示虚拟协议时间，可能跳过没有事件的等待区间；不会把动画停留时间作为硬件线时。
- **X1～X4**：勾选表示输入接低。可构造全高、多路低、断开或更换模号。实际模号和本轮锁定的 MH 分开显示。
- **X5**：点按产生 100 ms 低电平，也可分别按住、释放。按键高低各稳定 20 ms。初始松开需经过消抖确认，上电按住的规则有自动测试覆盖。
- **命令**：快捷发送 RD_NUM、指定模号的 START 和 OK；自定义输入可分段发送，收到 `)` 即执行，不自动追加行结束。
- **主板记录**：可编辑多行或片段，选择 CRLF、CR、LF 或不追加行结束。发送 end 同样使用所选行结束。
- **手动接管**：操作输入或发送数据会取消尚未执行的预设场景动作并开始播放，保留已经开始的帧及其结束事件。重置可回到 X1 低、X5 松开的初始状态。
- **数据包详情**：点击运动的数据包或日志中的串口文本，查看完整文本、可见 CR/LF 标记和 UTF-8 十六进制字节。仅串口筛选隐藏内部逻辑事件；日志最多显示 500 行。

六类场景为：完整查询与测试、连续记录转换、分段接收与长时间等待、模号不匹配、模号断开与恢复、X5 启动及忙时忽略。每个场景开始时独立重置，正常 end 不追加汇总帧。

## 架构

```text
界面动作 / 场景动作
       ↓
SimulationEngine：虚拟时钟、排队、暂停、单步
       ↓
BridgeProtocol：命令、模号、按键、记录、发送边界
       ↓
统一事件流 ──→ Controller：状态 / 串口日志 / 数据对照
       └────→ Laboratory：模型 / 接线 / 数据包 / 处理高亮
```

| 目录或入口 | 职责 |
| --- | --- |
| src/protocol | 可脱离浏览器测试的协议状态机及完整记录解析 |
| src/simulation | 确定性事件调度、播放与六类场景 |
| src/scene | Three.js 程序化模型、轨道镜头和数据包 |
| src/ui | 中文面板、日志、字节详情和响应式布局 |
| assets | 项目测试样本快照与来源校验信息 |
| vendor/three | 固定 r180 的运行依赖及 MIT 许可证 |
| tests | Node.js 行为与本机服务测试 |
| server.mjs | 仅供本机使用的只读静态服务 |

协议接口为 `setInputs(mask)`、`setX5(low)`、`feedHost(bytesOrText)`、`feedBoard(bytesOrText)`。引擎通过 `dispatch(action, timeMs)` 排队，`step()` 发布一个事件，`tick(deltaMs)` 按演示速度发布事件，`reset()` 清空旧队列。所有动作和内部截止时间共用一条有序时间线。

事件包含 `seq`、`timeMs`、`type`、`title`、`state`，按需附带 `channel`、`raw`、字节数组、转换记录和处理阶段。四种通道为 host-mcu、mcu-host、board-mcu、mcu-board。状态快照随事件保存，界面和三维场景使用同一快照；只在发布事件时改变显示状态。

发送模型按 115200 / 8N1 计算理论帧时长。发送开始后遇到模号失效，先产生当前完整帧的发送结束事件，再发送 ERR。测试主板每一整行完成校验后生成一条 JSON，所有组都参与校验，仅首组上传。首帧、帧间均没有超时。

## 协议依据与边界

实现依据为项目当前根目录 README，以及 `02 软件源码/顺天祥协议转换` 下 App/app_comm.c、App/app_comm.h、Control/input_control.c 和 Public/board_config.h。旧任务书与历史测试记录中的超时、整轮汇总及多组上传规则不作为当前规范。

- UART2：P1.2 RXD2、P1.3 TXD2，连接上位机。
- UART1：P3.0 RXD、P3.1 TXD，连接测试主板。
- X1～X5：P3.2～P3.6，低电平有效。
- 容量按 UTF-8 字节计算：单行 511、名称 31、单位 8、命令 23。
- 保留每条记录原有数值、单位和 OK/NG，不根据上下限重新判定；输出帧尾固定 CRLF。
- UTF-8、控制字符、所有测点组、保留键及数值结构均检查。旧会话结束或异常停止后，主板旧数据丢弃。

这是独立 JavaScript 协议行为模型，芯片内部模块、PCB 外观和接线走向均为教学示意。模型没有尺寸或真实硅片布局含义。输入数据按逻辑块到达，发送按完整帧建模；不执行 C51 指令，不模拟中断周期、字节级收发竞争、SRAM 环形区溢出和电气特性，也不连接实际串口。演示结果不能替代固件构建、波特率测量或实板吞吐量验收。

assets/sample-mapping.json 来自项目 `04 测试验证/results/sample_mapping.json`，连续样本和期望输出来自 `04 测试验证/串口测试数据`。快照让本目录可以独立运行；在完整项目中执行测试会核对 28 条映射快照与原资料相同。源资料变更后应同步快照并重新验证，来源与 SHA-256 见 assets/provenance.json。

## 验证

在本目录运行：

```powershell
node --test tests/protocol.test.js tests/server.test.js
```

自动验证覆盖 28 条逐字节样本、六条连续输入、16 种模号组合、四种 MH、分段和 CR/LF、74 秒等待、首组与完整行校验、JSON 转义、UTF-8、容量、错误恢复、X5 边界、发送完整性及播放调度。服务测试检查本地模块、依赖、样本、MIME 类型、路径边界以及运行源码没有外部资源地址。

开发期间的浏览器检查、截图与最终结果见本目录 `验证记录.md`。

可选浏览器回归使用 Playwright：在已有 Playwright 的开发环境运行 `node tests/browser-check.mjs`，或用 `--playwright=完整模块路径` 指定开发环境的 Playwright 入口；`STC_CHROME_PATH` 可指定已安装的 Chrome。此脚本自动启动独立的临时浏览器和本机服务，阻止所有非本机请求，验证六类场景及界面操作，并保存预览与 artifacts/browser-results.json。Playwright 不参与用户日常运行，也不需要随离线演示分发。
