# STC12C5A60S2 / 828C 协议转换

将测试主板的文本记录转换成 828C 上位机使用的 JSON。UART2 接收上位机命令，检测对应 X 输入低电平后，由 UART1 启动主板测试；主板每返回一条记录，就向上位机上传一条完整 JSON。

芯片为 **STC12C5A60S2**，内部 RC 配置 **22.1184 MHz**，两路串口均为 **115200、无校验、8 位数据、1 位停止位（8N1）**。使用者已确认原版本在该时钟下转换成功；本轮新增输入触发和首组格式的实物验收仍待完成。

## 接线与启动

| 功能 | MCU 引脚 | 连接说明 |
| --- | --- | --- |
| UART1 RX / TX | P3.0 / P3.1 | 接测试主板 TX / RX |
| UART2 RX / TX | P1.2 / P1.3 | 接上位机 TX / RX |
| X1 / X2 / X3 / X4 | P3.2 / P3.3 / P3.4 / P3.5 | 准双向输入、内部弱上拉，低电平有效 |

双方串口交叉连接并共地，串口电平须与板卡实际接口一致。

| 上位机命令 | 等待的输入 | 触发后 UART1 发送 | 本次返回的 MH |
| --- | --- | --- | --- |
| `(START,1)` | X1 为低 | `test\r\n` | `"1"` |
| `(START,2)` | X2 为低 | `test\r\n` | `"2"` |
| `(START,3)` | X3 为低 | `test\r\n` | `"3"` |
| `(START,4)` | X4 为低 | `test\r\n` | `"4"` |

1. 收到完整 START 后，只检查指定输入。已经为低时立即触发，不要求先变高，也不增加消抖延时。
2. 在 1000 ms 内检测到指定低电平才启动；到 1000 ms 仍未触发，向上位机回复一次 `{"Result":"ERR"}\r\n`，回到空闲。其他输入为低不触发。
3. 触发后只发一次 `test\r\n`，实际字节为 `74 65 73 74 0D 0A`。本次模号锁定，后续输入变化不会改号或重复启动。
4. test 全部发送完成后，开始 3 秒首条有效记录计时。超时回复一次 ERR；收到首条有效记录后，不设帧间超时。
5. 等待输入时继续处理上位机命令；新 START 替换旧会话并重新计时。正在输出 JSON 时先发完当前帧，再切换。

空闲和等待输入时，主板数据被丢弃；触发前清空旧接收内容，避免前一轮数据混入。

## 数据转换规则

主板记录格式：

```text
项目名称,上限,下限,单位,(测点=实测值,测点=实测值,...),OK/NG
```

每条完整记录输出一条 JSON，以英文标点编码，帧尾固定为 CRLF。**所有非空项目仅上传首组，保留测点、实测值和单位**；没有项目名称白名单，不固定测试数量或顺序。

| 主板记录 | 上位机 JSON（均另加 CRLF） |
| --- | --- |
| `D1-1,9.0,6.0,V,(2-5=12.6),NG` | `{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}` |
| `Open,10.0,0.0, ohm,(8-78=978.4,9-84=992.2,),NG` | `{"MH":"1","Result":"NG","Open":"8-78=978.4 ohm:NG"}` |
| `Short,99.9,2.0,Mohm,(),OK` | `{"MH":"1","Result":"OK","Short":"OK"}` |
| `Custom,10,0,,(p=1.250,q=2.500),OK` | `{"MH":"1","Result":"OK","Custom":"p=1.250:OK"}` |

- 非空值格式为 `测点=实测值 单位:结果`；单位为空时省去前面的空格。
- MH 来自当前 START 的通道。Result 来自当前记录末尾，统一为大写 OK/NG；前面的 NG 不影响后续 OK。
- 保留数值精度、正负号、科学计数法和单位大小写；去掉字段两端空格及制表符。不上传上下限，也不重新判断合格与否。
- 接收完整行后才能取得末尾结果；后续组仍校验结构、编码和数值，但不上传。缩短的是 UART2 输出时间，不是主板整行接收时间。
- 支持括号内末尾逗号。主板行结束支持 CRLF、CR、LF；输出一律 CRLF。
- 名称、单位、测点中的引号和反斜杠进行 JSON 转义；非 ASCII 内容要求 UTF-8，非法编码和控制字符报错。
- 每条 JSON 只有 MH、Result 和一个项目键。项目名不得为保留键 `MH` 或 `Result`，避免重复键。

主板 `test` 标记忽略；`end` 结束会话，不附加汇总、PASS 或另一条正常结果。首条有效记录之前直接收到 end，按无有效结果回复 ERR。结果逐条上传，不等待 end。

## 其他命令与异常

`(RD_NUM)` 查询软件默认模号，例如 `{"Result":"1"}\r\n`。默认值配置为 1，支持改为 1～4；该默认值不拦截其他有效 START，启动也不依赖查询。

上位机发送的单独 `OK` 确认识别后忽略，支持不带行结束或附 CRLF。固件不等待 ACK。括号命令收到 `)` 即可执行，也可附 CRLF。

格式错误、非法命令、超长或接收溢出统一回复 `{"Result":"ERR"}\r\n` 并结束当前会话。已经开始输出的合法 JSON 先完整发送，再输出 ERR；后续有效 START 可恢复。尚未收齐行结束的片段只缓存，不提前生成正常结果。

调试器可查看 `app_state` 与 `app_last_error`，它们不输出到串口。错误码：1 命令、2 数据格式、3 单行超长、4 UART1 溢出、5 UART2 溢出、6 首条记录超时、7 输入等待超时，0 为无错误。

```text
01 参考资料/                  原始说明、任务书和主板样本

  User/                      启动、初始化和主循环
  App/                       命令、会话、记录解析和流式 JSON
  Control/                   X1～X4 GPIO 配置与输入读取
  System/                    双串口基础驱动与通信毫秒计时
  Public/                    原厂 MCU 头、公共定义、板级配置
  Project.uvproj             Keil 工程
  .eide/                     EIDE 工程配置
04 测试验证/                 主机测试、构建脚本和验证记录
03 数据手册/                 STC12 数据手册（只保留一份纳入 Git）
```

公共类型和存储区宏集中在 Public_cfg.h；原厂 STC12C5A60S2.h 保持不变。自有 C 文件使用四空格、独立花括号、中文 `@brief / @param / @retval` 注释及内部/对外分区，参考 [RGBWIR4_PRS4_TestReader 的代码风格](https://github.com/happygithub1123/RGBWIR4_PRS4_TestReader)。

串口中断只搬运字节；解析和编码在主循环完成。不使用动态内存，不保存整轮结果，不另建完整 JSON 缓冲。接收区内的数据校验后，随编码消费并释放。

默认容量：单行 511 字节（不含 CR/LF）、名称 31 字节、单位 8 字节、命令 23 字节；UTF-8 按字节计数。UART1 环形区 768 字节，UART2 环形区 64 字节，各保留一个空槽。测点直接流式输出，没有额外短名称限制。超容量报 ERR，不静默截断。这些是固件内存预算，不是主板协议的固定长度。

## 构建与使用

在 STC-ISP 中选择内部 RC，确保实际频率与 `Public/board_config.h` 的 `PROJECT_FOSC_HZ=22118400UL` 相符。两路共享 BRT，1T、倍速；分频值 12、重装值 0xF4，理论波特率为 115200。生成波特率误差超过 2% 时拒绝编译。

打开 Keil `Project.uvproj`，选择唯一目标 **828C INTERNAL RC 22.1184MHz** 重建。EIDE 同样配置为该目标，使用 SMALL 内存模型及片内 XRAM 边界。

在仓库根目录用 Python 3 运行：

```powershell
python "04 测试验证/build_keil.py"
python "04 测试验证/run_tests.py"
```

构建脚本默认使用 `D:/Keil_v5`，可用 `--keil` 指定路径；`--fosc 22118400` 可显式指定内部 RC 频率。主机测试通过 vswhere 查找 Visual Studio C++ 工具链。脚本频率参数不会改写 IDE 配置，改变硬件频率时应同步板级配置和 IDE 时钟。

当前 HEX 输出到 `02 软件源码/顺天祥协议转换/BuildMeasured/Bridge828C.hex`，仅在本地保留。以本次构建退出成功和日志为准；失败时旧 HEX 可能仍存在。旧 Objects、Listings、BuildTest 等缓存不属于本轮交付产物。

本轮主机测试 **75 项全部通过**，包含 28 条样本逐字节比对、首组选择、四路低电平映射、1 秒边界、3 秒首条记录超时、重新 START、JSON 转义、UTF-8、分段、连续数据、缓冲边界和异常恢复。
