# STC12C5A60S2 / 828C 协议转换

将测试主板的文本记录转换成 828C 上位机使用的 JSON。UART2 接收上位机命令，立即核对 X1～X4 的实际模号，再由 UART1 启动主板测试；也可通过 X5 直接启动。主板每返回一条完整记录，就向上位机上传一条完整 JSON。

芯片为 **STC12C5A60S2**，内部 RC 配置 **22.1184 MHz**，两路串口均为 **115200、8 位数据、无校验、1 位停止位**。本轮 X5 按键消抖、时基和真实上位机验收仍待实物验证。

## 接线与启动

| 功能 | MCU 引脚 | 连接说明 |
| --- | --- | --- |
| UART1 RX / TX | P3.0 / P3.1 | 接测试主板 TX / RX |
| UART2 RX / TX | P1.2 / P1.3 | 接上位机 TX / RX |
| X1 / X2 / X3 / X4 | P3.2 / P3.3 / P3.4 / P3.5 | 准双向输入、内部弱上拉，低电平有效 |
| X5 启动按键 | P3.6 | 松开高、按下低，消抖后高→低启动一次 |

双方串口交叉连接并共地，串口电平须与板卡实际接口一致。

| 上位机命令 | 必须唯一为低的输入 | UART1 发送 | 本次返回的 MH |
| --- | --- | --- | --- |
| `(START,1)` | X1 为低 | `test\r\n` | `"1"` |
| `(START,2)` | X2 为低 | `test\r\n` | `"2"` |
| `(START,3)` | X3 为低 | `test\r\n` | `"3"` |
| `(START,4)` | X4 为低 | `test\r\n` | `"4"` |

1. 收到完整 `(START,x)` 后，一次读取 X1～X4。必须且只能有一路为低，并与 x 相同；不等待后续电平变化，不增加消抖延时。
2. 模号不一致、全部为高或多路为低时，立即向上位机回复一次 `{"Result":"ERR"}\r\n`，不发 test。修正输入后可直接重发匹配的 START，不要求重新触发 X5。
3. 核对成功只发一次 `test\r\n`，实际字节为 `74 65 73 74 0D 0A`。本次 MH 锁定，活动会话持续检测该模号。
4. 启动后持续等待主板记录，**不设置输入等待、首条记录或帧间超时**。主板沉默超过 3 秒也不会因此报 ERR；一条记录收完整后立即处理，不等待整轮结束。
5. 每次新 START 都重新核对输入，匹配即可建立新会话，包括模号断开后重新接回的情况。正在输出 JSON 时先发完当前帧，再执行新命令；新 START 核对失败则回复 ERR 并结束旧会话。

空闲时主板数据被丢弃；每次成功启动前清空旧接收内容，避免前一轮数据混入。

### X5 按键：按一下启动，松开继续

X5 是瞬时按键。先松开为高，再按下为低；高、低电平分别稳定 **20 ms** 后确认，只在高→低时启动一次。**上电已经按住不启动，须先松开再按。** X1～X4 不增加消抖或等待，仍按一次 GPIO 快照核对。

| 状态／操作 | 固件行为 |
| --- | --- |
| 空闲时按一下 X5，X1～X4 唯一有效 | 锁定模号，清旧接收数据，UART1 发一次 `test\r\n` |
| 空闲时按一下 X5，无模号或多路低 | UART2 回复一次 `{"Result":"ERR"}\r\n`，不发 test |
| 启动后松开或长按 X5 | 继续接收转换，不重复发送 test |
| 活动模号断开、改变或多路有效 | 停止旧会话并主动报一次 ERR，后续旧数据丢弃 |
| 接回模号，未重新按键 | 不自动恢复；再次松开、按下 X5 才重新确认模号 |
| 测试中再次按 X5 | 忽略，不排队；一直按到 end 也不补发 |
| 正常收到 end | 结束上传和旧模号监测，等待新启动 |

**START 保持独立。** 新的匹配 START 始终可以启动，不要求按 X5。模号断开后的恢复既可用新的有效按键，也可用新的有效 START；接回输入或 RD_NUM 查询本身不启动。

输入检测及消抖在主循环中非阻塞执行，发送 JSON、查询或 test 期间仍处理按键。忙时按下会被消耗，即使消抖确认前恰好结束测试也不会延迟启动；须松开稳定后再按。空闲时已接受的按键事件可等待当前查询／未完成命令的边界，松开不会取消；执行前重新核对锁定模号，模号失效取消该请求。有效 START 优先，不重复发送 test。

已经开始的合法 JSON、查询回复及 test 指令完整发送后才报错或切换，未发字节的 test 可以取消。Timer0 只提供约 1 ms 按键时基，内部计时不占用 X3/P3.4 输入；不增加输入等待、首帧或帧间超时。

## 数据转换规则

主板记录格式：

```text
项目名称,上限,下限,单位,(测点=实测值,测点=实测值,...),OK/NG
```

每条完整记录输出一条 JSON，以英文标点编码，帧尾固定为 CRLF。**所有非空项目仅上传首组，保留测点、实测值和单位**；没有项目名称白名单，不固定测试数量或顺序。

| 主板记录 | 上位机 JSON（均另加 CRLF） |
| --- | --- |
| `D1-1,9.0,6.0,V,(2-5=12.6),NG` | `{"MH":"1","Result":"NG","D1-1":"2-5=12.6 V:NG"}` |
| `Open,10.0,0.0, ohm,(8-78=978.4,9-84=992.2,),NG` | `{"MH":"1","Result":"NG","Open":"8-78=978.4 ohm:NG"}` |
| `Short,99.9,2.0,Mohm,(),OK` | `{"MH":"1","Result":"OK","Short":"OK"}` |
| `Custom,10,0,,(p=1.250,q=2.500),OK` | `{"MH":"1","Result":"OK","Custom":"p=1.250:OK"}` |

- 非空值格式为 `测点=实测值 单位:结果`；单位为空时省去前面的空格。
- MH 来自本次启动锁定的实际通道：START 已核对匹配，X5 则直接读取唯一有效模号。Result 来自当前记录末尾，统一为大写 OK/NG；前面的 NG 不影响后续 OK。
- 保留数值精度、正负号、科学计数法和单位大小写；去掉字段两端空格及制表符。不上传上下限，也不重新判断合格与否。
- 接收完整行后才能取得末尾结果；后续组仍校验结构、编码和数值，但不上传。缩短的是 UART2 输出时间，不是主板整行接收时间。
- 支持括号内末尾逗号。主板行结束支持 CRLF、CR、LF；输出一律 CRLF。
- 名称、单位、测点中的引号和反斜杠进行 JSON 转义；非 ASCII 内容要求 UTF-8，非法编码和控制字符报错。
- 每条 JSON 只有 MH、Result 和一个项目键。项目名不得为保留键 `MH` 或 `Result`，避免重复键。

主板 `test` 标记忽略；`end` 结束会话并解除旧模号监测，不附加汇总、PASS 或另一条正常结果。首条有效记录之前直接收到 end，按无有效结果回复 ERR。结果逐条上传，不等待 end。

## 其他命令与异常

`(RD_NUM)` 一次读取 X1～X4，唯一有效时返回对应 `{"Result":"x"}\r\n`（x 为 1～4），例如只有 X2 为低时返回 `{"Result":"2"}\r\n`；全部为高或多路为低时返回 `{"Result":"ERR"}\r\n`。查询不向主板发送 test，也不改变或结束当前测试会话。没有软件默认模号，启动不依赖查询。

RD_NUM 按新 828C 功能治具说明 PDF 返回 Result JSON，供上位机识别串口并绑定实际模号。所有回复使用英文引号，帧尾为 `0D 0A`。

活动模号失效由持续监测独立报错并结束会话。RD_NUM 可返回接回后的实际模号，但查询不自动恢复上传；随后发送匹配 START 即可重新启动，无需触发 X5。

上位机发送的单独 `OK` 确认识别后忽略，支持不带行结束或附 CRLF。固件不等待 ACK。括号命令收到 `)` 即可执行，也可附 CRLF。

格式错误、非法命令、START 模号无效、超长或接收溢出统一回复 `{"Result":"ERR"}\r\n` 并结束当前会话；RD_NUM 输入无效仅回复 ERR，保留当前会话。已经开始输出的合法 JSON 先完整发送，再输出 ERR；数据、通信或模号异常后均可用新的有效 START 恢复，也可释放 X5 后重新有效触发。尚未收齐行结束的片段只缓存，不提前生成正常结果。

调试器可查看 `app_state` 与 `app_last_error`，它们不输出到串口。错误码：1 命令、2 数据格式、3 单行超长、4 UART1 溢出、5 UART2 溢出、6 启动模号无效或治具模号失效，0 为无错误。RD_NUM 查询自身不修改会话错误码。

## 工程结构

```text
01 参考资料/                  原始说明、任务书和主板样本
02 软件源码/顺天祥协议转换/
  User/                      启动、初始化和主循环
  App/                       命令、会话、记录解析和流式 JSON
  Control/                   X1～X5 GPIO 配置、快照与唯一模号识别
  System/                    双串口基础驱动、按键消抖时基
  Public/                    原厂 MCU 头、公共定义、板级配置
  Project.uvproj             Keil 工程
  .eide/                     EIDE 工程配置
04 测试验证/                 主机测试、构建脚本和验证记录
03 数据手册/                 STC12 数据手册（只保留一份纳入 Git）
```

公共类型和存储区宏集中在 Public_cfg.h；原厂 STC12C5A60S2.h 保持不变。自有 C 文件使用四空格、独立花括号、中文 `@brief / @param / @retval` 注释及内部/对外分区，参考 [RGBWIR4_PRS4_TestReader 的代码风格](https://github.com/happygithub1123/RGBWIR4_PRS4_TestReader)。

串口中断只搬运字节；解析和编码在主循环完成。不使用动态内存，不保存整轮结果，不另建完整 JSON 缓冲。接收区内的数据校验后，随编码消费并释放。

默认容量：单行 511 字节（不含 CR/LF）、名称 31 字节、单位 8 字节、命令 23 字节；UTF-8 按字节计数。UART1 环形区 768 字节，UART2 环形区 64 字节，各保留一个空槽。测点直接流式输出，没有额外短名称限制。超容量报 ERR，不静默截断。这些是固件内存预算，不是主板协议的固定长度。

## 构建与使用

在 STC-ISP 中将内部 RC 设为 22.1184 MHz。UART1 和 UART2 均固定为：**115200、8 位数据、无校验、1 位停止位**，无需分别设置波特率。

打开 Keil `Project.uvproj`，选择唯一目标 **828C Protocol Conversion Project** 重建。EIDE 同样配置为该目标，使用 SMALL 内存模型及片内 XRAM 边界。

在仓库根目录用 Python 3 运行：

```powershell
python "04 测试验证/build_keil.py"
python "04 测试验证/run_tests.py"
```

构建脚本默认使用 `D:/Keil_v5`，可用 `--keil` 指定路径。时钟与串口参数固定在工程中；主机测试通过 vswhere 查找 Visual Studio C++ 工具链。

Keil 与构建脚本的 HEX 输出到 `02 软件源码/顺天祥协议转换/Objects/Bridge828C.hex`，仅在本地保留；EIDE 的输出根目录同样为 Objects，其构建器会在其中按目标建立子目录。以本次构建退出成功和日志为准；失败时旧 HEX 可能仍存在。旧 Project.hex、旧构建缓存及临时日志已清理，当前固件保留。下次编译会重新生成所需 OBJ、列表和日志文件。
